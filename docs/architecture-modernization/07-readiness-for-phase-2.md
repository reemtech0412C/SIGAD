## حفظ Git دون فقد تغييرات محلية

عند بدء B0.1، الإجراء الآمن المقترح:

1. أوقف تغييرات الملفات مؤقتًا وسجل `HEAD` وقائمة `git status --short --untracked-files=all`، مع حفظ منفصل لـ`git diff --cached --binary HEAD` و`git diff --binary` ونسخة من Git index. تؤخذ القائمة قبل إنشاء أي commit.
2. أنشئ نسخة محلية كاملة غير مدمرة للـcheckout، تشمل `.git` والملفات المتتبعة وغير المتتبعة والمحذوفة؛ تحقق من القائمة والبصمات قبل اعتبارها صالحة. احتفظ بها محليًا بصلاحيات وصول محدودة، ولا ترفعها.
3. بعد اعتماد D-09، أنشئ فرع الأساس المحدد بالخطة، ثم أضف الملفات صراحةً على دفعات. راجع كل `git diff --cached` وابحث عن الأسرار قبل commit. أبقِ الصور غير المحسوم مصيرها في النسخة الاحتياطية حتى اختيار LFS أو الاستبعاد.
4. لا تستخدم `git clean` أو `reset --hard` أو `stash -a` أو `git add -A`؛ ولا تستعد الملف المحذوف ضمنيًا. لا push. لا تعتبر الحالة محفوظة حتى يثبت manifest النسخة الاحتياطية ومراجعة commits ثم نظافة `git status`.

عند بداية المراجعة كان HEAD `371f0be`، وحالة Git تضم 67 ملفًا معدلًا، وملفًا محذوفًا، و500 ملفًا غير متتبع (`--untracked-files=all`). هذا التقرير نفسه ملف توثيق جديد غير متتبع؛ لا يحذف أو يستبدل أيًا من الحالة السابقة.

### قرار جغرافي مطلوب قبل تثبيت التصميم

نعم، يلزم قرار إداري قبل اعتماد `VALIDE` تلقائيًا في التصميم الجديد. الدليل الحالي يثبت سلوك التنفيذ فقط، لا تفويض التصديق: مسار الإنشاء الديناميكي يسمح لبعض أدوار الميدان بالإنشاء ويكتب `VALIDE`، بينما جرد الجغرافيا يسجل 32 قسمًا بحالة `statut_validation=VALIDE` مع `validation_administrative=A_VERIFIER`. أوصي بأن يكون الإنشاء `PROPOSE`، وتكون المصادقة بيد الجهة التي تسميها الإدارة؛ ولا يصبح المستوى صالحًا للتوزيع قبلها. يلزم اعتماد D-13 وتسمية السلطة في D-03. لا يغيّر هذا التقرير السلوك القائم.
