## B2.3-A — أساس تقني إضافي (2026-10-26)

أضيفت migration `0037_geo_foundation.sql` بثمانية جداول الهدف الواردة في خارطة الطريق، وبجدول `geo_sources` منفصل لتطبيع بيانات المصدر وإصداره واكتماله والتحقق منه. لا تحتوي جداول الجغرافيا التسعة على أي صف بعد migration؛ لا استيراد ولا backfill ولا تغيير في الجداول القديمة. أبقت migration الأنواع والقواعد والوحدات فارغة، فلا تُثبت مستوى إداريًا أو عددًا مختلفًا عليه. تبقى معرفات 23 ولاية و112 مديرية والعلاقات التاريخية في الجداول القديمة دون تعديل.

يشترط النموذج مصدرًا متحققًا مناسبًا لنوع الوحدة، ويفصل `statut_validation` عن `statut_operationnel`، ويبدأ السجل بـ`PROPOSE`/`INACTIF`. الاعتماد يتطلب مصدرًا، وتفويضًا موثقًا، ومقترحًا ومصدقًا مختلفين؛ لا توجد صلاحية أو مسارات اعتماد مفعلة. تحمي قيود العلاقات من الآباء غير الصالحين، وتداخل فترات الأبوة، والدورات، وتكرار الأشقاء وفق الاسم المعياري. لا تسمح قاعدة البيانات بحذف وحدة أو علاقة؛ تُؤرشف الوحدة وتُغلق العلاقة زمنيًا. يحفظ سجل النسخ تغييرات الوحدة والعلاقة والأسماء البديلة والأكواد الخارجية لمزامنة لاحقة.

أضيفت أنواع TypeScript وعقود قراءة versioned، ووظائف شجرية حتمية، ووظائف قراءة للأبناء والبحث والأسلاف. تطبق الوظائف قائمة GID أو نطاقًا وطنيًا مصدره جلسة الخادم على الصفوف قبل pagination؛ النطاق الفارغ أو الغائب يمنع النتائج. لم تُسجل routes جديدة ولم تتغير مصفوفة الصلاحيات (216 مسارًا)، ولم تُربط `portees_acces` بالنموذج الجديد أو تستخدم جداول B2.2 في قرار وصول. اختبارات النموذج تستخدم مصادر وأنواع ووحدات تحمل صراحة `TEST_ONLY`؛ لا تحفظ هذه fixtures في migrations.
