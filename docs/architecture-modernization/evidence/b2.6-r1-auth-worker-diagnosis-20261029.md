# B2.6-R1 — Authentication / Worker verification evidence

## Cause et portée du correctif

- Le dernier échec complet connu (`verify-20261027T112606191Z.txt`, lignes 4438–4441) montre un `404` attendu sur la révocation d’un appareil appartenant à un autre compte après **6 864 446 ms (114,4 min)**, puis `GET /api/auth/session` en `401`.
- Le compte propriétaire avait été ouvert par activation initiale. `auth.routes.ts` fixe cette session et son cookie à **15 min** (activation initiale et MFA compris). La confirmation MFA termine l’état d’activation mais ne renouvelle pas l’échéance. `auth.middleware.ts` refuse toute session expirée. Le dump D1 de l’ancien échec n’a pas été conservé : l’expiration de cette ligne ne peut donc pas être relue, mais la durée observée dépasse le TTL défini et explique le `401` sans impliquer l’approbation de l’appareil.
- `appareils.ts` invalide les sessions liées lors d’une suspension ou révocation; l’approbation n’exécute pas cette invalidation. Le test vérifie maintenant explicitement le TTL initial, puis réalise une connexion normale avec MFA et utilise la session fraîche pour la chaîne d’approbation. Aucun code applicatif ni règle d’accès n’a été modifié.
- Le test `ClientLocal` borne chaque requête Worker à 30 s et inclut méthode/chemin dans l’erreur, sans journaliser cookie, jeton ou corps.

## Wrangler et environnement

- Versions constatées : Node `v24.19.0`, Wrangler `4.151.3`, Miniflare `5.20261019.1-beta`, workerd `1.20261019.1`.
- Sous le sandbox standard, une sonde loopback temporaire vers `127.0.0.1` a échoué avec `fetch failed` / `EACCES`. `wrangler d1 migrations apply --local` a alors échoué avant la liste des migrations et avant le démarrage de Worker; le journal debug se termine dans `[worker eval]:35:22`, sans cause réseau plus précise. Ce n’est pas une réponse HTTP de l’application.
- Un essai initial utilisant le répertoire Temp isolé du sandbox a aussi eu `EPERM` à la suppression du fichier de codes de test. Les essais suivants ont repris `C:\Users\Lenovo\AppData\Local\Temp`, utilisé par le run réussi du 27 octobre; ils n’ont pas reproduit cet `EPERM`.
- Avec l’accès loopback local autorisé, Wrangler a appliqué les migrations uniquement à D1 temporaire, Worker a démarré et les tests ont terminé avec code 0. Aucune liaison distante Staging/Production n’est configurée; `ENVIRONMENT=staging` n’est qu’une variable de caractérisation locale.
